# JAIRO Cloud メタデータ取得・検索ツール

JAIRO Cloud が停止している間の応急手段として作成した、機関リポジトリの本文 PDF の保存状況を調べるツールです。
本文 PDF が Internet Archive の Wayback Machine に保存されているかを調べ、保存版へのリンクを示します。
用途に応じて、次の2つの方法を使い分けます。

- **CSV 出力ツール**：機関リポジトリから IRDB にハーベストされたメタデータを取得し、保存状況を CSV ファイルに出力します。出力した CSV ファイルは、静的な HTML ページで簡易に検索できます。ページは、担当者向けの `viewer_staff.html` と、一般公開向けの `docs/sample/viewer_public.html` の2種類です。
- **ブラウザ拡張機能**：IRDB の詳細ページに、保存版へのリンクを表示します。CSV を作らずに使えるので、登録件数が多い機関に向いています。

## ご注意

- 元の機関リポジトリにあるすべての PDF ファイルが、Wayback Machine に保存されているとは限りません。保存されるのは、クローラが到達したものだけです。
- ランディングページが Wayback Machine に保存されていても、PDF ファイルは保存されていないことがあります。
- 新しく登録されたアイテムほど、保存されていない傾向があります。国際農研のリポジトリ（`jircas.repo.nii.ac.jp`）で 2026-11-07 に確認したところ、全体では 82% のアイテムが Wayback Machine に保存されていました。レコード番号が 2000900 未満のアイテムでは 95% が保存されていたのに対し、2000900 以上では 42% でした。
- CSV 出力ツールは、Wayback Machine に保存された各アイテムのメタデータからライセンスを判定します。メタデータが保存されていないアイテムは判定できません。国際農研のリポジトリ（906 件）で 2026-11-08 に確認したところ、メタデータを取得できたのは 677 件で、CC ライセンスと判定できたのは 34 件（うち PDF を取得できるものは 33 件）でした。
- 提供されているファイルのライセンスやメタデータの詳細は、IRDB 上で確認してください。
- 取得した PDF を再公開したり、他機関に提供したりするときは、元のファイルのライセンスに従ってください。Internet Archive の利用条件と、IRDB 上のメタデータに書かれたライセンス情報を確かめ、提供機関にも確認してください。

## 使い方

Python 3 が必要です。
追加のインストールはありません。

```bash
WB_CONTACT="連絡先メールアドレス(任意)" python wb_fulltext_csv.py --host jircas.repo.nii.ac.jp --out result.csv
```

| オプション | 内容 |
| --- | --- |
| `--host` | 対象リポジトリのホスト名（必須） |
| `--query` | IRDB OpenSearch の `q`（既定: `--host` と同じ） |
| `--out` | 出力する CSV（既定: `wayback_fulltext.csv`） |
| `--bulk` / `--no-bulk` | `/record/` 配下を一括で分割取得して突き合わせる（既定）。`--no-bulk` ではアイテムごとに照会する |
| `--license` / `--no-license` | Wayback に保存された各アイテムのメタデータ（WEKO3 の `export/json`）から、ライセンス情報を取得する（既定）。初回は数百件で数十分かかる。`--no-license` では取得せず、ライセンスの列を空にする。`--no-bulk` のときも取得しない |
| `--capture-before DATE` | 採用する保存版の日時の上限（既定: 制限なし）。UTC で、この日時より前（未満）の保存版から最新のものを選ぶ。`YYYY-MM-DD`、`YYYYMMDD`、`YYYYMMDDhhmmss` で指定する。日付だけなら 00:00:00 UTC（日本時間 09:00）で、`2026-10-28` は「2026-10-28 00:00:00 UTC より前」。ライセンス判定に使うメタデータにも適用する |
| `--limit N` | 動作確認用に、先頭の N 件だけを処理する |
| `--refresh` | IRDB の一覧を取り直す |
| `--cache-dir` | キャッシュの保存先（既定: `.wb_cache`） |
| `--interval` | リクエスト間隔の秒数（既定: 1.0） |
| `--env-file` | 設定ファイル（既定: カレントディレクトリの `.env`。無ければ読まない） |

処理は次の順に進みます。

1. IRDB の [OpenSearch API](https://support.irdb.nii.ac.jp/ja/about/manual/opensearch) で、対象ホストのアイテムを列挙します。
2. 本文 URL を Wayback Machine の CDX API に照会します。
3. PDF ごとに、最新の保存を選びます（`--capture-before` を指定したときは、その日時より前の保存のうち最新のもの）。あわせて、同じ PDF の保存どうしで内容の要約値（digest）を比べます。
4. Wayback に保存された各アイテムのメタデータを取得し、権利情報とファイルのライセンス種別から、CC ライセンスかどうかを判定します（`--no-license` のときは行いません）。

既定の `--bulk` は、アイテムごとに照会するかわりに `/record/` 配下をまとめて取得するので、通信回数が少なくて済みます。

中断しても、同じ `--cache-dir` で再実行すれば、取得済みの分を再利用します。
キャッシュは、IRDB の検索条件とホストごとに分けて保存します。
CDX のキャッシュには照会条件（取得する項目とフィルタ）も記録し、条件が違う古いキャッシュは削除して取り直します。
digest の取得を加えたバージョンに更新した後の初回の実行では、CDX の照会をやり直します（`--bulk` なら数ページ分ですが、`--no-bulk` ではアイテムごとに照会し直すので、数百件で数時間かかります）。
ライセンス情報もキャッシュに残るので、2回目以降は、Wayback に新しい保存が現れたアイテムだけを取り直します。
図書館の担当者だけが使う場合は、`--no-license` を付けると、ライセンス情報の取得を省けます。

`WB_CONTACT` は User-Agent に付ける連絡先で、環境変数か `.env` で渡します。
Wayback のレート制限は公表されていません。
既定では1秒間隔で照会し、429 や 503 が返ったときは待ってから再試行します。
CDX の応答には、1回あたり 20〜60 秒かかることがあります。

テストは次のコマンドで実行します。

```bash
python test_wb_fulltext_csv.py
```

### 設定ファイル（`.env`）

オプションは、カレントディレクトリの `.env` に書いておけます。
`.env.example` を `.env` という名前でコピーし、値を書き換えてください。
`.env` に `WB_HOST` を書いておけば、`python wb_fulltext_csv.py` だけで実行できます。

```dotenv
WB_HOST=jircas.repo.nii.ac.jp
WB_CONTACT=連絡先メールアドレス
WB_OUT=result.csv
WB_LICENSE=false
WB_CAPTURE_BEFORE=2026-10-28
```

- キーは、オプション名を大文字にして `-` を `_` に置き換え、先頭に `WB_` を付けたものです（`--cache-dir` は `WB_CACHE_DIR`）。連絡先の `WB_CONTACT` も書けます。
- `--limit` と `--refresh` は書けません。どちらも1回の実行だけで使う指定で、`.env` に書くと毎回効いてしまうためです。
- `WB_BULK` と `WB_LICENSE` の値は、`true` か `false` です（`1` と `0`、`yes` と `no`、`on` と `off` も使えます）。
- `WB_CAPTURE_BEFORE` を空にする（`WB_CAPTURE_BEFORE=`）と、制限なしになります。環境変数やコマンドライン（`--capture-before ""`）の空文字でも、`.env` の値を打ち消せます。
- 1行に1項目を書きます。`#` で始まる行はコメントです。行の途中からはコメントにできません。
- 値は `"` か `'` で囲んでもかまいません。
- 文字コードは UTF-8 です。BOM 付きでも読めます。
- 同じ項目をコマンドライン、環境変数、`.env` のうち複数で指定したときは、この順に優先します。どこにも指定しなければ、既定値を使います。
- `.env` には連絡先のメールアドレスを書くことがあるので、`.gitignore` で Git の管理から外しています。

## 取得する情報

PDF ファイルごとに1行を出力します。
保存が見つからないアイテムは、状態だけを書いた1行になります。

| 列 | 内容 |
| --- | --- |
| `status` | `ok`（PDF の保存を確認）/ `after_cutoff`（`--capture-before` の日時以降の保存しか無い。リンクは出さない）/ `no_capture`（保存なし）/ `no_pdf`（PDF 以外のみ、または無効な記録）/ `cdx_error`（照会に失敗） |
| `title`, `issn`, `publicationName`, `volume`, `number`, `startingPage`, `endingPage`, `publicationDate` | IRDB のメタデータ |
| `updated` | IRDB の更新日（個別の登録日ではありません） |
| `irdb_url`, `record_url`, `record_id` | IRDB の詳細ページ、リポジトリの詳細ページ、レコード番号 |
| `file_url` | 本文 PDF の元の URL |
| `capture_timestamp`, `capture_date` | 採用した保存の日時と日付（`--capture-before` が無ければ最新の保存） |
| `mimetype`, `length` | CDX の値（参考。PDF でも `mimetype` が `application/octet-stream` になることがあります） |
| `n_captures` | そのファイルの保存回数（取得できた有効な保存の数。`--capture-before` の日時以降も含む） |
| `item_files_captured` | そのアイテムで保存を確認でき、採用できた PDF の数（`after_cutoff` のファイルは数えない） |
| `archive_url` | Wayback Machine 上の PDF ファイルの URL（`…/web/{timestamp}id_/{original}`） |
| `license_status` | `--no-license` / `--no-bulk` のときは空。`cc`（CC ライセンス。NC や ND の条件が付くものも含む）/ `check`（要確認。権利情報とファイルのライセンス種別が食い違う）/ `not_cc`（権利情報はあるが CC ではない）/ `no_rights`（権利情報なし）/ `no_json`（メタデータを取得できない） |
| `license`, `rights`, `rights_uri`, `licensetype` | 判定した CC ライセンスの名前（例: `CC BY 4.0`）、権利情報の本文と URI、ファイルのライセンス種別（WEKO3 の値） |
| `license_capture_date`, `license_source_url` | 判定に使ったメタデータの保存日と、Wayback Machine 上の URL |
| `capture_digest` | 採用した保存の digest（Wayback Machine が保存したバイト列の SHA-1。欠けていれば空） |
| `digest_variants` | そのファイルの保存のうち、比べられる digest の種類の数 |
| `integrity_status` | 保存どうしの digest の比較結果。`consistent`（2回以上の保存がすべて同じ）/ `changed`（バイト列の違う保存がある。内容の変更とは限らない）/ `single`（比べられる保存が1件だけ）/ `unknown`（digest の欠けた保存があり、判定できない。`cdx_error` の行も `unknown`） |
| `digest_first_seen` | 採用した保存と同じ digest を最初に観測した日（この内容になった日とは限りません） |
| `later_digest_date` | 採用した保存より後に、別の digest を最初に観測した日（変更が起きた日とは限りません） |

### 実行結果を読むときの注意

- 複数のファイルのうち一部だけが保存されている場合も、`ok` になります。ファイルの不足は検出できません。
- `capture_date` は、Wayback が最後に保存した日です。その後にリポジトリ側でファイルが差し替えられていても、反映されていません。
- digest は、Wayback Machine が保存したバイト列の SHA-1 です（`id_` で取得した本文の SHA-1 と一致することを確かめています）。比較は、取得できた保存どうしで行います。
- `consistent` は「取得できた比較可能な保存が、すべて同じバイト列だった」という意味です。内容が正しいこと（真正性）は保証しません。たとえば、最初の保存より前に改ざんされていれば、改ざん後の内容どうしで一致します。
- `changed` は「バイト列の違う保存がある」という意味で、内容が変わったとは限りません。内容の変更（正規の差し替えか改ざんかは区別できません）のほかに、保存が途中で切れている場合（1 MiB や 5 MiB ちょうどで切れた例があります）や、圧縮（gzip）されたまま保存されている場合も `changed` になります。
- `changed` でも、PDF へのリンク（`archive_url`）は出します。PDF を開いて内容を確かめ、利用するかどうかを判断してください。
- `single` は「比べられる保存が1件だけ」という意味です。Wayback に1回しか保存されていないとは限りません（status 200 以外の記録は数えていません）。
- `--capture-before` は、改ざんの前の保存を選びやすくする手段です。指定した日時より前の保存が改ざんされていないことは保証しません。日時は UTC で、指定した日時ちょうどの保存は含みません。
- `--capture-before` を指定すると、指定した日時より前のメタデータが無いアイテムは、ライセンスが `no_json` になります。実行ログに、`no_json` の理由ごとの件数を出します。

## 閲覧ページの設置

閲覧ページは、CSV を表示し、テキストボックスへの入力で絞り込む単体のページです。
外部のライブラリは使いません。
用途に応じて、次の2種類を使い分けます。
ページのタイトルと説明文は、設置する機関に合わせて書き換えてください。

| ファイル | 用途 |
| --- | --- |
| `viewer_staff.html` | 担当者向け。すべての PDF へのリンクと、ライセンスの判定結果を表示します。「CC ライセンスのものだけを表示する」で絞り込めます。 |
| `docs/sample/viewer_public.html` | 一般公開向け。CC ライセンスを確認できた PDF だけにリンクを表示します。初期状態では、CC ライセンスのものだけを表示します。冒頭にあるサンプルの説明は書き換えてください。 |

一般公開向けのページには、ライセンス情報を含む CSV（`--no-license` も `--no-bulk` も付けずに出力したもの）を使います。
ライセンスの列が無いか空の CSV では、PDF へのリンクを1件も表示しません。

1. 任意の Web サーバー（機関の Web サーバーや GitHub Pages など）の同じフォルダに、閲覧ページと出力した CSV を置きます。CSV のファイル名は `result.csv` にします。
2. 閲覧ページを開くと、同じ場所の `result.csv` を自動で読み込みます。

国際農研のデータを使ったサンプルを、GitHub Pages で公開しています。
https://tzhaya.github.io/jc-fallback/sample/viewer_public.html

手元で試すときは、CSV のあるフォルダで簡易サーバーを起動します。

```bash
python -m http.server 8000
```

その後、`http://localhost:8000/viewer_staff.html` を開きます。

閲覧ページをファイルとして直接開いた場合（`file://`）は、ブラウザの制限により、CSV を自動では読み込めません。
画面の「CSV ファイルを選択」から選ぶか、ドラッグ&ドロップで渡してください。
ファイルは端末の中だけで処理し、外部には送信しません。

絞り込みは、CSV のすべての列を対象にします。
空白で区切って複数の語を入力すると、すべての語を含む行だけが残ります。
全角と半角、英字の大文字と小文字は区別しません。
読み込む CSV のファイル名を変えるときは、閲覧ページの `CSV_URL` を書き換えます。

ページの配色と文字組みは、[デジタル庁デザインシステム](https://design.digital.go.jp/dads/)を参考にしています。

## ブラウザ拡張機能（IRDB の詳細ページにリンクを表示）

`extension/` は、[IRDB](https://irdb.nii.ac.jp/) の詳細ページに、Wayback Machine の保存版へのリンクを表示する Chrome / Edge 用の拡張機能（Manifest V3）です。
CSV を作らずに使えるので、登録件数が多く、CSV の作成に時間がかかる機関に向いています。
表示は一般の利用者向けで、本文 PDF へのリンクは CC ライセンスの資料にだけ出します。

- 対象は、JAIRO Cloud の資料だけです。`*.repo.nii.ac.jp` のほか、独自ドメインで運用しているリポジトリ（`repository.naro.go.jp` など）も対象です。ほかのリポジトリの資料のページでは、何も表示しません。
- 独自ドメインのリポジトリは、`extension/lib.js` の `CUSTOM_HOSTS` に一覧で持っています。一覧に無いリポジトリを対象にするときは、ホスト名を一覧に足してください。
- ランディングページ（`/records/{id}`）の保存版へのリンクは、すべての資料に表示します。
- 本文 PDF の保存版へのリンクは、IRDB の「権利情報」に CC ライセンス（NC や ND の条件が付くものを含む）が書かれている資料にだけ表示します。ただし、公開日（Available）より前のファイルと、アクセスが制限されているファイルには表示しません。
- リンクを表示する前に、Wayback Machine に保存状況を問い合わせます。保存を確認できたものだけをリンクにし、保存日を添えます。確認が終わるまでは項目名をリンクにせず、点の連続で通信中であることを示します。
- 問い合わせには、1件あたり数十秒かかることがあります。問い合わせに失敗したときは、最新の保存版へのリンクを表示します（開けない場合があります）。
- 問い合わせの結果は、6時間ブラウザに保存します。

### インストール（パッケージ化されていない拡張機能として読み込む）

1. このリポジトリをダウンロードし、展開します。
2. Chrome では `chrome://extensions`、Edge では `edge://extensions` を開きます。
3. 「デベロッパー モード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」（Edge では「展開して読み込み」）を押し、`extension` フォルダを選びます。
5. IRDB の資料の詳細ページ（例: https://irdb.nii.ac.jp/07496/0006016487 ）を開くと、表の上にリンクが表示されます。

拡張機能のファイルを更新したときは、拡張機能の一覧で再読み込みのボタンを押してから、IRDB のページを開き直してください。

テストは、Node.js 標準のテストランナーで実行します（追加のインストールはありません）。

```bash
node --test extension/test/*.test.js
```
