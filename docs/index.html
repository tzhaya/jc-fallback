JAIRO Cloud メタデータ取得・検索ツール

JAIRO Cloud が停止している間の応急手段として作成した、機関リポジトリの本文 PDF のアーカイブ状況を調べるツールです。

概要

本文 PDF が Internet Archive の Wayback Machine にアーカイブされているかを調べ、アーカイブ版へのリンクを示します。用途に応じて、次の2つの方法を使い分けます。

  • CSV 出力ツール：機関リポジトリから IRDB にハーベストされたメタデータを取得し、アーカイブ状況を CSV ファイルに出力します。出力した CSV ファイルは、静的な HTML ページで簡易に検索できます。ページは、担当者向けの viewer_staff.html と、一般公開向けの docs/sample/viewer_public.html の2種類です。Python の標準ライブラリだけで動作し、追加のインストールは要りません。
  • ブラウザ拡張機能：IRDB の詳細ページに、アーカイブ版へのリンクを表示します。CSV を作らずに使えるので、登録件数が多い機関に向いています（後述）。

ご注意

  • このツールは、Internet Archive の Wayback Machine（CDX API とアーカイブ版）を利用しています。Internet Archive の提供するサービスと、サイトのアーカイブを続けている運営者に感謝します。利用にあたっては、Internet Archive の利用条件に従ってください。このツールの結果を研究成果として公表するときは、Internet Archive を資料として参考文献に挙げてください。
  • 元の機関リポジトリにあるすべての PDF ファイルが、Wayback Machine にアーカイブされているとは限りません。アーカイブされるのは、クローラが到達したものだけです。
  • ランディングページが Wayback Machine にアーカイブされていても、PDF ファイルはアーカイブされていないことがあります。
  • 新しく登録されたアイテムほど、アーカイブされていない傾向があります。国際農研のリポジトリ（jircas.repo.nii.ac.jp）で 2026-11-07 に確認したところ、全体では 82% のアイテムが Wayback Machine にアーカイブされていました。レコード番号が 2000900 未満のアイテムでは 95% がアーカイブされていたのに対し、2000900 以上では 42% でした。
  • CSV 出力ツールは、Wayback Machine にアーカイブされた各アイテムのメタデータからライセンスを判定します。メタデータがアーカイブされていないアイテムは判定できません。国際農研のリポジトリ（906 件）で 2026-11-08 に確認したところ、メタデータを取得できたのは 677 件で、CC ライセンスと判定できたのは 34 件（うち PDF を取得できるものは 33 件）でした。
  • 提供されているファイルのライセンスやメタデータの詳細は、IRDB 上で確認してください。
  • 取得した PDF を再公開したり、他機関に提供したりするときは、元のファイルのライセンスに従ってください。Internet Archive の利用条件と、IRDB 上のメタデータに書かれたライセンス情報を確かめ、提供機関にも確認してください。

免責事項

プログラムの動作は作者が確認していますが、万全であることは保証できません。数万件単位などの大量のデータ取得は試していません。

利用とその結果については、利用者の責任で判断してください。作者はその責任を負いません。

使い方

Python 3 が必要です。次のコマンドで、対象リポジトリのホスト名を指定して実行します。

WB_CONTACT="連絡先メールアドレス(任意)" python wb_fulltext_csv.py --host jircas.repo.nii.ac.jp --out result.csv
オプション内容
--host対象リポジトリのホスト名（必須）
--queryIRDB OpenSearch の q（既定: --host と同じ）
--out出力する CSV（既定: wayback_fulltext.csv）
--bulk / --no-bulk/record/ 配下を一括で分割取得して突き合わせる（既定）。--no-bulk ではアイテムごとに照会する
--license / --no-licenseWayback にアーカイブされた各アイテムのメタデータ（WEKO3 の export/json）から、ライセンス情報を取得する（既定）。初回は数百件で数十分かかる。--no-license では取得せず、ライセンスの列を空にする。--no-bulk のときも取得しない
--capture-before DATE採用するスナップショットの日時の上限（既定: 制限なし）。UTC で、この日時より前（未満）のスナップショットから最新のものを選ぶ。YYYY-MM-DD、YYYYMMDD、YYYYMMDDhhmmss で指定する。日付だけなら 00:00:00 UTC（日本時間 09:00）で、2026-10-28 は「2026-10-28 00:00:00 UTC より前」。ライセンス判定に使うメタデータにも適用する
--limit N動作確認用に、先頭の N 件だけを処理する
--refreshIRDB の一覧を取り直す
--cache-dirキャッシュの保存先（既定: .wb_cache）
--intervalリクエスト間隔の秒数（既定: 1.0）
--env-file設定ファイル（既定: カレントディレクトリの .env。無ければ読まない）

処理は次の順に進みます。

  1. IRDB の OpenSearch API で、対象ホストのアイテムを列挙します。
  2. 本文 URL を Wayback Machine の CDX API に照会します。
  3. PDF ごとに、最新のスナップショットを選びます（--capture-before を指定したときは、その日時より前のスナップショットのうち最新のもの）。あわせて、同じ PDF のスナップショットどうしで内容の要約値（digest 値）を比べます。
  4. Wayback にアーカイブされた各アイテムのメタデータを取得し、権利情報とファイルのライセンス種別から、CC ライセンスかどうかを判定します（--no-license のときは行いません）。

既定の --bulk は、アイテムごとに照会するかわりに /record/ 配下をまとめて取得するので、通信回数が少なくて済みます。

中断しても、同じ --cache-dir で再実行すれば、取得済みの分を再利用します。キャッシュは、IRDB の検索条件とホストごとに分けて保存します。CDX のキャッシュには照会条件（取得する項目とフィルタ）も記録し、条件が違う古いキャッシュは削除して取り直します。digest 値の取得を加えたバージョンに更新した後の初回の実行では、CDX の照会をやり直します（--bulk なら数ページ分ですが、--no-bulk ではアイテムごとに照会し直すので、数百件で数時間かかります）。ライセンス情報もキャッシュに残るので、2回目以降は、Wayback に新しいスナップショットが現れたアイテムだけを取り直します。図書館の担当者だけが使う場合は、--no-license を付けると、ライセンス情報の取得を省けます。

WB_CONTACT は User-Agent に付ける連絡先で、環境変数か .env で渡します。Wayback のレート制限は公表されていません。既定では1秒間隔で照会し、429 や 503 が返ったときは待ってから再試行します。CDX の応答には、1回あたり 20〜60 秒かかることがあります。

設定ファイル（.env）

オプションは、カレントディレクトリの .env に書いておけます。.env.example を .env という名前でコピーし、値を書き換えてください。.env に WB_HOST を書いておけば、python wb_fulltext_csv.py だけで実行できます。

WB_HOST=jircas.repo.nii.ac.jp
WB_CONTACT=連絡先メールアドレス
WB_OUT=result.csv
WB_LICENSE=false
WB_CAPTURE_BEFORE=2026-10-28
  • キーは、オプション名を大文字にして - を _ に置き換え、先頭に WB_ を付けたものです（--cache-dir は WB_CACHE_DIR）。連絡先の WB_CONTACT も書けます。
  • --limit と --refresh は書けません。どちらも1回の実行だけで使う指定で、.env に書くと毎回効いてしまうためです。
  • WB_BULK と WB_LICENSE の値は、true か false です（1 と 0、yes と no、on と off も使えます）。
  • WB_CAPTURE_BEFORE を空にする（WB_CAPTURE_BEFORE=）と、制限なしになります。環境変数やコマンドライン（--capture-before ""）の空文字でも、.env の値を打ち消せます。
  • 1行に1項目を書きます。# で始まる行はコメントです。行の途中からはコメントにできません。
  • 値は " か ' で囲んでもかまいません。
  • 文字コードは UTF-8 です。BOM 付きでも読めます。
  • 同じ項目をコマンドライン、環境変数、.env のうち複数で指定したときは、この順に優先します。どこにも指定しなければ、既定値を使います。
  • .env には連絡先のメールアドレスを書くことがあるので、.gitignore で Git の管理から外しています。

取得する情報

PDF ファイルごとに1行を出力します。PDF のスナップショットが見つからないアイテムは、状態だけを書いた1行になります。

列内容
statusok（PDF のスナップショットを確認）/ after_cutoff（--capture-before の日時以降のスナップショットしか無い。リンクは出さない）/ no_capture（今回の照会で PDF のスナップショットが見つからなかった。ビューアの表示は「アーカイブ版なし」）/ no_pdf（スナップショットはあるが、PDF 以外のみ、または無効な記録。ビューアの表示は「PDFなし」）/ cdx_error（照会に失敗）
title, issn, publicationName, volume, number, startingPage, endingPage, publicationDateIRDB のメタデータ
updatedIRDB の更新日（個別の登録日ではありません）
irdb_url, record_url, record_idIRDB の詳細ページ、リポジトリの詳細ページ、レコード番号
file_url本文 PDF の元の URL
capture_timestamp, capture_date採用したスナップショットの日時と日付（--capture-before が無ければ最新のスナップショット）
mimetype, lengthCDX の値（参考。PDF でも mimetype が application/octet-stream になることがあります）
n_capturesそのファイルのスナップショット数（取得できた有効なスナップショットの数。--capture-before の日時以降も含む）
item_files_capturedそのアイテムでスナップショットを確認でき、採用できた PDF の数（after_cutoff のファイルは数えない）
archive_urlWayback Machine 上の PDF ファイルの URL（…/web/{timestamp}id_/{original}）
license_status--no-license / --no-bulk のときは空。cc（CC ライセンス。NC や ND の条件が付くものも含む）/ check（要確認。権利情報とファイルのライセンス種別が食い違う）/ not_cc（権利情報はあるが CC ではない）/ no_rights（権利情報なし）/ no_json（メタデータを取得できない）
license, rights, rights_uri, licensetype判定した CC ライセンスの名前（例: CC BY 4.0）、権利情報の本文と URI、ファイルのライセンス種別（WEKO3 の値）
license_capture_date, license_source_url判定に使ったメタデータのアーカイブ日と、Wayback Machine 上の URL
capture_digest採用したスナップショットの digest 値（Wayback Machine が記録したバイト列の SHA-1。欠けていれば空）
digest_variantsそのファイルのスナップショットのうち、比べられる digest 値の種類の数
integrity_statusスナップショットどうしの digest 値の比較結果。consistent（2回以上のスナップショットがすべて同じ）/ changed（バイト列の違うスナップショットがある。内容の変更とは限らない）/ single（比べられるスナップショットが1件だけ）/ unknown（digest 値の欠けたスナップショットがあり、判定できない。cdx_error の行も unknown）
digest_first_seen採用したスナップショットと同じ digest 値を最初に観測した日（この内容になった日とは限りません）
later_digest_date採用したスナップショットより後に、別の digest 値を最初に観測した日（変更が起きた日とは限りません）
possibly_truncated採用したスナップショットより length が大きく、digest 値の違うスナップショットがあれば 1（採用したアーカイブ版が途中で切れている可能性がある）。比べる相手は全期間のスナップショットです。空は「この条件に当たらない」という意味で、切れていないことを確かめたものではありません
larger_capture_datepossibly_truncated が 1 のとき、条件を満たすスナップショット（採用したものより length が大きく、digest 値の違うもの）のうち、length がいちばん大きいもののアーカイブ日（--capture-before の日時より後のスナップショットも含む）
alt_capture_date別のアーカイブ版のアーカイブ日。条件を満たすスナップショットのうち、--capture-before の日時より前で length がいちばん大きいもの（同じ長さなら新しいもの）。無ければ空
alt_archive_url別のアーカイブ版の原本の URL（id_ 指定）。無ければ空
  • 複数のファイルのうち一部だけがアーカイブされている場合も、ok になります。ファイルの不足は検出できません。
  • capture_date は、Wayback が最後にアーカイブした日です。その後にリポジトリ側でファイルが差し替えられていても、反映されていません。
  • digest 値は、Wayback Machine が記録したバイト列の SHA-1 です（id_ で取得した本文の SHA-1 と一致することを確かめています）。比較は、取得できたスナップショットどうしで行います。
  • consistent は「取得できた比較可能なスナップショットが、すべて同じバイト列だった」という意味です。内容が正しいこと（真正性）は保証しません。たとえば、最初のスナップショットより前に変更や差し替えがされていれば、変更後の内容どうしで一致します。
  • changed は「バイト列の違うスナップショットがある」という意味で、内容が変わったとは限りません。内容の変更（意図した差し替えかどうかは、digest 値からは分かりません）のほかに、アーカイブ版が途中で切れている場合（1 MiB や 5 MiB ちょうどで切れた例があります）や、圧縮（gzip）されたままアーカイブされている場合も changed になります。
  • changed でも、PDF へのリンク（archive_url）は出します。PDF を開いて内容を確かめ、利用するかどうかを判断してください。
  • Wayback Machine は、大きなファイルを途中までしかアーカイブしないことがあります（1 MiB や 5 MiB ちょうどで切れた例があり、どれも PDF として開けませんでした）。採用したスナップショットより length が大きく、digest 値の違うスナップショットがあれば、possibly_truncated を 1 にし、別のアーカイブ版（alt_archive_url）を示します。採用するスナップショットは変えません。
  • possibly_truncated は、CDX の length（圧縮後の WARC レコード長。PDF 本文の実サイズではありません）の比較からの推定です。意図した差し替えでファイルが小さくなった場合にも 1 になります。圧縮（gzip）されたままアーカイブされた版があるときも、その版の length がわずかに大きく出て、1 になることがあります。jircas で確かめた、length の差が 2% 未満の 2 件は、どちらも別の版が gzip のままアーカイブされた同じ内容でした（そのうち 1 件を Chrome でダウンロードすると展開され、採用したアーカイブ版と同じ PDF になりました）。スナップショットが1件だけのものや、すべてのスナップショットが同じように切れているものは検出できません。
  • 別のアーカイブ版は、比較したスナップショットのうち length がいちばん大きいものです。完全な版であることは保証しません。--capture-before を指定したときは、その日時より前のスナップショットからだけ選びます。指定の日時より後にしか length が大きいスナップショットが無いときは、alt_archive_url は空で、larger_capture_date だけが入ります。
  • single は「比べられるスナップショットが1件だけ」という意味です。Wayback に1回しかアーカイブされていないとは限りません（status 200 以外の記録は数えていません）。
  • --capture-before は、内容が変わる前のアーカイブ版を選びやすくする手段です。指定した日時より前のスナップショットの内容が正しいことは保証しません。日時は UTC で、指定した日時ちょうどのスナップショットは含みません。
  • --capture-before を指定すると、指定した日時より前のメタデータが無いアイテムは、ライセンスが no_json になります。実行ログに、no_json の理由ごとの件数を出します。

閲覧ページの設置

閲覧ページは、CSV を表示し、テキストボックスへの入力で絞り込む単体のページです。外部のライブラリは使いません。用途に応じて、次の2種類を使い分けます。ページのタイトルと説明文は、設置する機関に合わせて書き換えてください。

  • viewer_staff.html（担当者向け）：すべての PDF へのリンクと、ライセンスの判定結果を表示します。「CC ライセンスのものだけを表示する」で絞り込めます。アーカイブ日の下に、digest 値の比較結果と、途中で切れている可能性の注意と、別のアーカイブ版へのリンクを表示します。
  • docs/sample/viewer_public.html（一般公開向け）：CC ライセンスを確認できた PDF だけにリンクを表示します。初期状態では、CC ライセンスのものだけを表示します。途中で切れている可能性がある PDF には、リンクの下に注意と別のアーカイブ版へのリンクを表示します。冒頭にあるサンプルの説明は書き換えてください。

一般公開向けのページには、ライセンス情報を含む CSV（--no-license も --no-bulk も付けずに出力したもの）を使います。ライセンスの列が無いか空の CSV では、PDF へのリンクを1件も表示しません。

  1. 任意の Web サーバー（機関の Web サーバーや GitHub Pages など）の同じフォルダに、閲覧ページと出力した CSV を置きます。CSV のファイル名は result.csv にします。
  2. 閲覧ページを開くと、同じ場所の result.csv を自動で読み込みます。

閲覧ページをファイルとして直接開いた場合は、ブラウザの制限により、CSV を自動では読み込めません。画面の「CSV ファイルを選択」から選ぶか、ドラッグ&ドロップで渡してください。ファイルは端末の中だけで処理し、外部には送信しません。

絞り込みは、CSV のすべての列を対象にします。空白で区切って複数の語を入力すると、すべての語を含む行だけが残ります。全角と半角、英字の大文字と小文字は区別しません。読み込む CSV のファイル名を変えるときは、閲覧ページの CSV_URL を書き換えます。

ブラウザ拡張機能

extension/ は、IRDB の詳細ページに、Wayback Machine のアーカイブ版へのリンクを表示する Chrome / Edge 用の拡張機能（Manifest V3）です。CSV を作らずに使えるので、登録件数が多く、CSV の作成に時間がかかる機関に向いています。表示は一般の利用者向けで、本文 PDF へのリンクは CC ライセンスの資料にだけ出します。

  • 対象は、JAIRO Cloud の資料だけです。*.repo.nii.ac.jp のほか、独自ドメインで運用しているリポジトリ（repository.naro.go.jp など）も対象です。ほかのリポジトリの資料のページでは、何も表示しません。
  • 独自ドメインのリポジトリは、extension/lib.js の CUSTOM_HOSTS に一覧で持っています。一覧に無いリポジトリを対象にするときは、ホスト名を一覧に足してください。
  • ランディングページ（/records/{id}）のアーカイブ版へのリンクは、すべての資料に表示します。
  • 本文 PDF のアーカイブ版へのリンクは、IRDB の「権利情報」に CC ライセンス（NC や ND の条件が付くものを含む）が書かれている資料にだけ表示します。ただし、公開日（Available）より前のファイルと、アクセスが制限されているファイルには表示しません。
  • リンクを表示する前に、Wayback Machine にアーカイブ状況を問い合わせます。スナップショットを確認できたものだけをリンクにし、アーカイブ日を添えます。確認が終わるまでは項目名をリンクにせず、点の連続で通信中であることを示します。
  • 問い合わせには、1件あたり数十秒かかることがあります。問い合わせに失敗したときは、最新のスナップショットへのリンクを表示します（開けない場合があります）。
  • 最新のスナップショットより length が大きく、digest 値の違うスナップショットがあるときは、アーカイブ版が途中で切れている可能性があるとして、本文 PDF のリンクの下に注意と、別のアーカイブ版（いちばん大きいもの）へのリンクを表示します。判定は CSV 出力ツールの possibly_truncated と同じです。
  • 問い合わせの結果は、6時間ブラウザに保存します。
  • プライバシー：閲覧中の資料のリポジトリ上の URL（本文ファイルとランディングページ）が、Internet Archive（web.archive.org）に送られます。Internet Archive は、あなたの IP アドレスを受け取ります。送られた情報の扱いは、Internet Archive のプライバシーポリシーに従います。この拡張機能は、IRDB と Internet Archive 以外にはデータを送らず、個人情報を収集しません。

インストール（パッケージ化されていない拡張機能として読み込む）

  1. GitHub のリポジトリをダウンロードし、展開します。
  2. Chrome では chrome://extensions、Edge では edge://extensions を開きます。
  3. 「デベロッパー モード」をオンにします。
  4. 「パッケージ化されていない拡張機能を読み込む」（Edge では「展開して読み込み」）を押し、extension フォルダを選びます。
  5. IRDB の資料の詳細ページ（例: https://irdb.nii.ac.jp/07496/0006016487）を開くと、表の上にリンクが表示されます。

拡張機能のファイルを更新したときは、拡張機能の一覧で再読み込みのボタンを押してから、IRDB のページを開き直してください。

テストは、Node.js 標準のテストランナーで実行します（追加のインストールはありません）。

node --test extension/test/*.test.js
